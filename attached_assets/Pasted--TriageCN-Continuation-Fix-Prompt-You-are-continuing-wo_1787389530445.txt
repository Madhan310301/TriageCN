# TriageCN — Continuation & Fix Prompt

You are continuing work on the existing **TriageCN / Analyst Cockpit** app (the
"Personalised Vulnerability Triage" prototype already running at the current
preview URL, built on the real `vulnerabilities.csv` (540 rows), `profiles.json`
(3 orgs), and `gold_set.csv`). Do **not** rebuild from scratch — the scoring
engine, tiering logic, and gold-set validation are already correct (ρ = 1.00 for
both Global Retail Bank and Agile Cloud Tech Startup, and the Municipal Utility
Provider "no ground truth" limitation is already stated honestly). The job now
is to fix concrete usability and completeness problems visible in a walkthrough
recording of the current build, so it actually earns marks on the judging
rubric instead of losing them to avoidable polish issues.

Fix the following, in priority order. Each item names exactly what's wrong and
what "done" looks like.

## 1. The page header is clipped and unreadable
On every view, the page title (should read something like "Personalised
Vulnerability Triage") is cut off behind the sticky "temporary development
preview" banner at the top of the viewport — only a fragment like
"...mageON Vulnerability triage" is visible. Add top padding/margin to the app
shell so the real header always clears the preview banner, and re-check at the
top of every scroll position, not just after scrolling down.

## 2. The negative test is hard proof for 25% of the rubric — it must be open by default, not a toggle
The "Negative-test examples · 4 WITHHELD PRODUCTS" panel currently sits
collapsed with its toggle switched **off**. A judge who doesn't think to flip it
never sees the single most important piece of evidence that this is
personalisation and not a severity sort. Change the default state to **expanded**,
and make sure it surfaces the exact known cases:
- `CVE-2024-1851` (Embedded IoT Gateway, CVSS 10.0, not KEV) — rank 27 of 540 for
  Global Retail Bank despite the perfect CVSS score, because it isn't one of the
  bank's two critical products.
- `CVE-2023-3539` (Identity Provider SaaS, CVSS 10.0, not KEV) — rank 44 of 540
  for Agile Cloud Tech Startup, and a **different** rank (211 of 540) for
  Municipal Utility Provider — same CVE, different excluded rank per org, driven
  by that org's own weights. Show both ranks side by side so the "different org,
  different outcome" point is visible without narration.

## 3. Prove personalisation actually happens live — don't just state it
The recording never clicks between Global Retail Bank, Agile Cloud Tech
Startup, and Municipal Utility Provider — it only ever shows the bank's queue.
Confirm (and if broken, fix) that clicking a different organisation card at the
top of Overview:
- Re-sorts the Priority Queue for that org's own weights in well under 10
  seconds, with no reload.
- Updates the four stat tiles (Risk Surface, Critical Assets, CISA KEV, Urgent
  Band) and the Explanation panel to match the newly selected org.
- Updates which two `critical_products` are treated as tier `critical_asset`.

This is the single "minimum demonstration" requirement from the brief ("Two
profiles produce visibly different top-five lists") — it has to work in one
click, on camera, not just be true in the data.

## 4. The other three nav items (Priority queue, Validation, Scoring method, Data sources) need real, distinct content
The recording only ever shows the Overview tab. Overview already contains a
priority queue, a gold-set validation card, and an explanation panel, so if the
dedicated **Priority queue**, **Validation**, **Scoring method**, and **Data
sources** pages just repeat Overview verbatim (or are empty), that reads as
dead navigation to a judge who clicks around. Each should either:
- show something Overview doesn't (e.g. **Priority queue** = the full 540-row
  sortable/searchable table rather than the top-10 preview; **Scoring method** =
  the weighted-severity formula plus each org's three weights and the
  percentile-band thresholds, spelled out; **Data sources** = the three file
  names, row counts, and the "no live API calls" statement), or
- be removed from the sidebar if they're not going to hold distinct content —
  a shorter, fully-real nav beats a longer one with stubs.

## 5. Show the "general" (non-critical-asset) tier somewhere in the UI
Every row visible in the recording is tagged "Critical asset." Stage 1/2 of the
brief requires that non-critical rows are scored and tagged `tier: general`,
never dropped — but if the UI only ever surfaces critical-asset rows in the
default view, a judge has no way to see that the "no hard exclusion" design
choice is real. Add a visible filter or second section (e.g. "Also scored, not
currently critical for this org") so both tiers are inspectable, not just
asserted in a README.

## 6. Clean up what a judge would notice as sloppy
- The floating "Made with Replit" / "Build for free" badges sit directly over
  live content (e.g. covering part of the Cross-organisation lens table in the
  Municipal Utility Provider row). Confirm these don't obscure data during the
  actual demo, or publish the app so the dev-preview banner and badges disappear
  entirely — this alone removes two distractions at once.
- The org cards show a "top 0.88 / top 0.90 / top 0.94" label with no visible
  legend. Either label it explicitly (e.g. "URGENT threshold: top 12th
  percentile") or drop it — an unexplained number reads as noise next to the
  otherwise well-labelled tiles.

## After the fixes: re-verify against the judging protocol
Once the above is done, walk through the exact demo-time protocol from the
challenge brief end to end and confirm each step actually works on screen,
not just in the data:
1. Load an unseen 4th profile (add one manually to `profiles.json` to test)
   and confirm the queue re-ranks with zero code changes.
2. Click between all three real orgs and narrate which profile fields changed
   the result.
3. Click one queue item and confirm the explanation panel updates before you
   say anything.
4. Trace one claim back to its row in `vulnerabilities.csv`.
5. Show the negative test open by default and defend the ranking.
6. State the Municipal Utility Provider gold-set limitation out loud, pointing
   at the "Validation Boundary" card that already says it well.

Don't touch the scoring formula, the tiering rule, or the gold-set numbers —
those are correct and validated. This pass is entirely about making the
already-correct engine visible, demoable, and free of avoidable rough edges.
